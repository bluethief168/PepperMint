从这里开始

椒图密码生成器是一款随单个 HTML 文件交付、在当前浏览器里运行的确定性密码派生工具。它把你提供的秘密、特征码和选定参数交给既有 Argon2id 流程，再把派生字节转换为字符密码或英文单词口令。相同的有效输入、相同的参数与相同的派生协议，会得到相同结果。生成日期、等待时间、中文或英文界面都不是秘密，也不会作为密码计算输入。

这个工具不是网站账号系统，也不会替你修改网站上的密码。它提供的是一串可以拿去设置账号密码的结果。你仍然需要在正确的网站完成改密、确认新密码能够登录，并保存账号自身的恢复方式。软件也没有云端找回主密码或 Pepper 的功能；失去关键输入后，不能依靠这份 HTML 自动恢复秘密。

首次使用建议先用完全虚构的资料练习生成、导出、导入和再次生成。确认理解“本地历史”和“脱敏文件”的区别，再处理真实账号。文中示例都是讲解结构的示例，不应直接拿来当作真实主密码。整个帮助正文已经内置，打开它不需要网络；只有你主动点击末尾的外部参考资料时，浏览器才会前往对应网站。

第一次生成与复现

第一步，打开可信来源的完整文件，选择中文或 English。中文页首名称是“椒图密码生成器”，英文页首名称是“PepperMint Password Generator”。语言只改变说明文字；英文单词口令始终使用原来的英文词表，不会因为选中文就换成中文词表。阅读帮助或切换语言不会替你改写输入框里的内容。

第二步，在常规版输入一个足够强的主密码，再填写能够稳定识别账号的特征码，例如域名、账号别名与自定版本的组合。第三步，选择字符密码或单词口令，并按目标网站实际要求决定长度、字符类别、分隔符等选项。第四步，点击生成，等待真实计算完成，再使用结果旁边的复制按钮。不要把“开始出现进度”误认为结果已经可用。

第五步，导出当前配置，并在适当的秘密保管位置保存原来的主密码；专业版还要保存原来的手工 Pepper。第六步，在新的测试页面导入这份配置、补回秘密、再次生成，逐字符确认与第一次一致。完成这次演练后才在网站上使用。若已有真实账号密码，复现时必须恢复原参数，不能凭印象重新选一个看上去差不多的方案。

主密码与安全边界

主密码是确定性方案的重要秘密。应当足够长、难猜、独立使用，避免姓名、生日、电话号码、影视台词、键盘规律，或者把一个泄露过的短密码简单加上年份。长度可以帮助提高猜测成本，但“很长”本身不代表不可预测：一整句广为人知的名言，也可能被攻击者优先尝试。选择你能可靠保管和准确输入的秘密，比追求奇怪的拼写更实用。

可以采用由可靠随机过程选取的多个互不相关词语，或者由可信密码管理器生成并保存的长随机字符串。本程序接受主密码为空而仅输入特征码的兼容行为被完整保留，但不建议把公开的域名单独当作真正的秘密来源。若没有高质量的主密码或私密 Pepper，输出看起来复杂也不能消除来源可猜的问题。

不要把所有秘密只存一处，也不要仅凭记忆承担无法找回的风险。根据自己的威胁和恢复需求安排可靠的备份。NIST 的公开建议强调长度、不同服务使用不同密码以及密码管理器的价值；这些是一般安全原则，不等同于本工具获得了任何认证。为账号启用其支持的多因素认证或通行密钥，可以补充密码本身无法解决的风险。

特征码的命名规则

特征码用于区分不同服务、账号或密码版本。它不需要像主密码那样保密，但必须可以准确恢复。你可以为新的账号采用固定的结构，例如 example.com|personal|v1，并记录自己是否包含子域名、是否用邮箱全称、字母是否小写。上述示例不是程序强制执行的格式；软件不会替你从网址中提取域名，也不会自动去除协议、斜杠或额外空格。

原有代码将规范化后的主密码和特征码直接拼接，再进行后续域分隔处理，二者之间没有新增长度编码。例如主密码 ab 与特征码 c，和主密码 a 与特征码 bc，具有相同拼接文本。这是现有协议的设计事实，本次没有改动。实际使用应保持主密码边界和特征码规则稳定，不能把不同字段组合必然对应不同输出当作保证。

一个账号需要换新密码时，可以为新方案记录新的特征码版本，再在网站上实际完成改密。但复现旧密码必须用旧版本。不要直接修改仅存的一份配置后删除原记录。特征码同时用于历史名称和单文件下载名称，下载文件名的合法化处理只影响文件名，不会把替换后的下划线重新写回特征码。

常规版与专业版

常规版采用既有兼容预设：内存 328506 KiB、迭代次数 7、并行度 1，以及随程序内置的固定 Pepper。主界面不要求你手工填写这些值。常规版适合希望减少参数管理的人，但它的计算负担仍然取决于设备和浏览器。不要把“常规”理解为每一台手机都必然很快，也不要为恢复旧密码自行换到专业版并使用另一个参数组合。

专业版允许指定 Pepper、内存、迭代次数和并行度。界面初始数值中的 65536 KiB、3、1 是原有默认值，不是对所有设备的通用性能承诺。所有整数参数都经过原有校验，并受底层实现和浏览器可表示范围限制。切换模式会改变有效参数的来源；即使两边界面看起来相似，也应以实际保存的配置为准。

常规版内置 Pepper 能从源文件中读到，因此是公开兼容常量，不是只有你知道的第二把钥匙。专业版的手工 Pepper 只有在确实随机、确实私密并独立保管时，才可能提供额外秘密来源。二者名字相同，并不意味着安全角色相同。模式字段本身不应被当成独立秘密，真正决定结果的是既有派生流程使用的实际数据和参数。

Pepper 的生成与保存

专业版的 Pepper 输入框允许留空；这表示本次使用空 Pepper，不会自动生成一个随机值。点击随机生成才会使用浏览器安全随机数接口产生新内容。旁边的长度框表示下次生成的字符数量。它不是保存下来的种子，也不是仅凭该数字就能重建的密钥。再次点击随机生成通常会得到新的 Pepper，进而改变用它派生的密码。

随机生成后应当把完整文本准确保存在你选定的秘密保管位置。不能只记录“64 位”“512 位”或某个日期标签：字符数、编码位数与实际秘密信息不是一回事，旧版复制参数中的 Pepper 标签也不能代替原文。本次没有改写这些原有复制格式，因此这里特别解释其用途限制。真正复现时需要原来的字符序列，空格与符号也不可凭记忆替换。

清空 Pepper 只清除当前输入框，并不代表已经撤销它参与生成的网站密码，也不代表删除了其他历史、文件或剪贴板副本。若丢失某个专业配置使用的私密 Pepper，重新随机生成不能恢复原结果。改变 Pepper 应作为有记录的新密码迁移处理，先确保账号仍然可以登录和修改，再实施替换。

内存参数 m

内存输入采用 KiB，而不是字节或十进制 KB。1024 KiB 等于 1 MiB，65536 KiB 等于 64 MiB。右侧的人类可读容量是辅助显示，参与算法的是原来的整数内存参数。提高内存通常会增加计算资源成本，也可能让移动设备、受限网页容器或其他占用内存较多的环境无法分配足够空间。

本版本只按 Argon2 规范校验内存范围：m 为正整数，单位 KiB，满足 8×p≤m≤4294967295；t 为 1 至 4294967295，p 为 1 至 16777215。原先额外设置的约 4 GiB 内存上限已取消，兼容计算路径的默认内存预算也按规范范围同步调整。规范允许不代表当前设备或计算实现一定能分配成功；分配失败会报错，不会自动缩小参数。实际占用还包括运行时、输出缓冲和其他开销。

为一个全新账号确定配置时，可在计划用来恢复的最弱设备上测试可接受的资源开销，再保存这组精确数值。对于已经设置好的密码，内存不足应先释放资源、关闭不必要的页面，或换到能够运行原参数的可信设备。降低 m 后得到的是另一套派生结果，不能解决原密码的复现问题。

迭代 t 与并行度 p

迭代次数 t 表示 Argon2 的遍数。增加它一般会增加等待时间和每次猜测的计算负担，但真实速度与设备、内存、实现和后台负载有关。程序要求它为正整数，并限制在 Argon2id 的三十二位参数范围之内。允许输入的巨大整数只是协议范围，不能当作日常推荐值。一次等待数小时甚至数天的配置，可能让正常恢复也变得困难。

并行度 p 表示 Argon2 的 lane 数。它不是保证浏览器同时启动同样数量 CPU 线程的开关。本程序保留原有执行引擎与线程策略，没有为了界面升级重新调度计算。改变 p 会改变算法布局和结果，即使某个设备上的耗时几乎没变，也不能认为密码不变。程序的既有上限为 16777215，同时仍须满足内存与输出长度等其他校验条件。

对于新方案，应把恢复设备兼容性、可承受等待和秘密质量一同考虑。对于旧方案，m、t、p 都应照原值恢复。仅为了追求“更安全”而随手加大一个参数，然后继续把新结果当旧密码使用，会导致登录失败。若决定升级成本，应生成新版本、在网站完成改密、测试成功后再更新自己的恢复记录。

字符密码的全部选项

字符密码由启用的数字、大写字母、小写字母和自定义符号候选池映射得到。默认长度仍是 16，本次没有更改。目标网站允许时，可以为新密码选择更长的长度，例如 20 或更多字符，但应先确认该网站是否实际完整接收，以及是否有特殊符号限制。很长的输出不是增加主密码熵的魔法；攻击者仍然可能从弱主密码入手。

自定义符号经过原有“可打印 ASCII 过滤和去重”处理，可打印范围是码点 32 至 126。重复项会被去重，保留的字符顺序影响候选池。全角符号、表情等不会按中文视觉上的“符号”自动加入该池。ASCII 空格属于这个范围，也可能通过自定义符号参与输出。不要整理或重新排序旧配置中的符号字符串后，仍期待必然得到原密码。

排除易混淆字符会移除 O、0、I、l、1、|，适合某些手工抄写场景，但它改变候选池。“强制每类至少出现一次”则启用既有策略映射和对应域标签；长度必须容纳每个有效类别至少一个字符。开启与关闭会走不同的既有派生路径。所有这些选项都应作为恢复记录的一部分，而不是只记住长度。

英文单词口令

单词模式使用随文件内置的 EFF 词表，并在计算前检查词表内容与顺序的完整性。默认单词数量仍为 6。程序不是按你的界面语言翻译选中的单词，也不是在线请求单词服务。中文界面与英文界面输入完全一致时，单词序列同样一致。更换词表、重新排序或用同义词替换都会破坏这套复现约定，因此本次完全保留原词表。

分隔符输入框决定单词之间插入什么文本，默认是普通半角连字符。空字符串表示不加分隔符，空格与连字符则是不同内容。“每个单词首字母大写”只按原规则改变词首形式，不会自动开启其他复杂度策略。数量、分隔符与大小写选项都应完整保存；尤其要区分普通连字符、长横线以及看上去类似的全角标点。

单词口令通常更便于读写，但并不是所有网站都允许其长度或分隔符。不要在生成后随手删掉某个单词、改几个字母或截取前半段，然后只保存原配置：那些手工编辑不会被程序记住。若网站有必须包含数字或符号的规则，应选择它接受的方案并重新设置，而不是误以为单词模式必然满足字符模式的类别开关。

真实进度与预计完成时点

真实进度由 Argon2id 内部 slice 完成事件报告，不是按动画速度假装计算已经前进。显示可以在已确认的进度之间平滑过渡，进度观察器不会向派生输入追加数据。已流逝时间主要用于用户观察；剩余时间依据原有整体速率和近期速率估计，初期样本不足时显示等待或正在建立速率是正常状态。

预计总耗时，即已流逝加预计剩余，大于 3600000 毫秒时，会额外显示预计完成日期与时间；等于或小于一小时则不显示。完成时点按照本机当前时间加预计剩余计算，采用本机时区，包含跨天日期。它会随原有进度刷新而更新，不是预约，也不是保证。设备休眠、浏览器挂起、温度限制、系统负载以及系统时钟调整都可能改变实际完成时间或显示时点。

当核心算完后，仍可能进行输出映射、校验与清理。应以明确的完成状态和结果区域为准。终止按钮沿用原有取消流程；计算失败不会被显示层替换成另一种算法或偷偷降低参数。帮助面板只是同页阅读视图，打开时不会主动取消任务；但操作系统自身的挂起行为仍然可能影响等待。

本地历史的真实含义

点击保存到历史会保存当前完整配置，有匹配的生成结果时也会一起保存。记录以特征码显示，每次新增一个编号，不覆盖同名条目。每页展示二十条，没有由界面设定的总条数上限，但浏览器存储空间始终有限。保存结果会区分已保存在此浏览器与仅本页暂存，后者在关闭页面后可能丢失，不能被当作已经完成备份。

最需要注意的是：原有本地历史包含明文主密码、Pepper 和结果，没有因为本次界面美化变成加密保险库。能够读取该浏览器存储的人或软件可能看到这些秘密。隐藏输入框或隐藏结果只改变屏幕显示，不能加密历史数据。共享电脑、公共设备或可能被他人访问的浏览器配置不适合保存真实秘密历史。

历史归属于浏览器存储环境，不会写进下载的 HTML。复制程序文件、换一个浏览器、清理站点数据、使用无痕窗口，都可能影响可访问性。删除所有历史按原有逻辑立即执行并保留当前表单与结果；它不会去删除下载文件、系统备份或剪贴板副本。这里明确说明这些边界，是为了帮助正确使用，历史模块本身没有改写。

导出、导入与恢复

导出当前配置和导出全部历史生成的是不含秘密的文件，主密码、Pepper 原文和生成结果不会写入这些导出数据。文件记录了模式、特征码、长度、类别、参数等恢复所需的非秘密配置。常规模式恢复时继续使用内置预设；专业模式如果原来使用私密 Pepper，就必须在导入之后补回它。脱敏文件没有把秘密加密藏起来，而是直接不包含它们。

现有导出采用 JSONC 风格的行尾中文注释，并兼容原有纯 JSON。为了保持原文件协议、导入规则和复制行为，本次没有根据界面语言翻译序列化的字段、注释、文件名或恢复参数文本。英文用户可以在本指南的参数说明中阅读对应含义。不要因为看不懂注释而随意改写 mode、gen、protocol 或数字类型，也不要把说明文字当成可执行脚本。

导入单配置恢复当前表单，导入合集则追加历史，二者不同。单文件名称来源于特征码，不合法的文件名字符会在名称里替换为下划线。导入旧版带有结果的配置时，显示原结果并不代表已重新计算验证。最可靠的恢复演练是补回原秘密、按原配置重新生成并比对。恢复参数复制文本也不能代替完整的秘密备份。

代码组织与数据流

代码仍以原有单文件结构组织：页面标记提供输入和结果节点，样式描述布局；内嵌兼容资源与 Unicode 数据支持固定行为；计算资源实现哈希与 Argon2id；应用脚本连接表单、引擎、映射、进度、剪贴板和配置历史。语言层与帮助层独立于原有派生流程；两处显示修复用于提示旧结果和重置配置恢复后的进度。本次参数范围更新仅移除 m、t、p 处理中的额外范围限制，并将兼容核心的内存预算调整到规范范围。哈希、内存块计算、输入编码、词表、输出映射和配置协议均保持不变。

一次生成大致经历这些阶段：清理旧结果并设置忙碌状态，检查资源完整性，规范化确定性输入，校验表单与参数，形成输出规格和配置快照，运行核心自检，构造域分隔文本与盐文本，调用计算引擎，执行输出映射，保存当前结果及恢复说明，最后释放资源和恢复界面。实际异常分支与取消检查依旧由原应用负责。

语言层不传入新的 hash 参数，不改写输入 value、checkbox 状态、模式 data 属性或存储协议。它只对受控的界面文案节点及可访问性属性显示翻译，并避开密码结果、历史标题、配置文本和脚本数据。帮助内容是静态解释，不参与任何派生。理解这一边界有助于检查未来修改：翻译显示名称不应演变为翻译秘密、词表或协议标签。

Unicode 与输入精确性

主密码、特征码、Pepper 和单词分隔符经过固定 Unicode 15.0.0 NFC 规范化。采用固定表的目的，是避免不同浏览器所依赖的 Unicode 版本差异改变规范化结果。UTF-8 编码对孤立代理项的替换规则也属于现有约定。不能为了代码看起来简洁就换成系统自身的另一套规范化策略，更不能在翻译时改写这些输入。

NFC 不等于自动纠错。它不会把所有长得相像的字母、全角标点或空格变成同一字符。为降低误操作导致无法复现密码的风险，本版本对主密码、特征码和专业版手工 Pepper 额外采用一条固定输入规则：参与派生前自动忽略首尾的普通半角空格（ASCII U+0020），但内容中间的普通空格仍然保留。这一规则只针对普通半角空格；首尾的回车、换行、Tab、全角空格以及其他 Unicode 空白字符不会被自动忽略，仍会影响有效输入和最终结果。因此复制粘贴秘密时仍应检查是否夹入换行或其他不可见字符。视觉上相同不应当替代实际配置比对。对于长期使用的秘密和标识，应有可靠的原文保存方式。

生成流程可能按既有规范化规则把输入框值更新为规范化文本，这不是语言切换行为。复现排查时，先确认来自同一个原始配置和秘密来源，而不是人工重新敲写一遍去猜差别。自定义符号另有 ASCII 过滤与去重规则，应结合字符模块说明理解；它与主密码的 Unicode 支持不是同一回事。

派生域、盐与输出映射

普通字符分支使用 v1 与 PwdGen-Salt-v1 前缀，强制类别分支使用 v2-policy 与 PwdGen-Salt-v2-policy，单词分支使用 v1-words 与 PwdGen-Salt-v1-words。前缀后按照原有竖线拼接格式组织文本。盐文本在这个可复现工具中是确定性构造的；不要把它误读为每次点击都生成随机盐的服务器密码存储方案。实际编码与调用细节以随文件保留的源码为准。

内部 Hash 长度也由输出规格计算。普通字符模式取长度三倍与 64 的较大者；类别策略取长度六倍加 96 与 96 的较大者；单词模式取数量六倍与 64 的较大者，并受参数边界校验。由此可见，改变输出长度不仅是把某个固定结果截短。不能假定二十位密码一定以前十六位形式包含原来的十六位密码。

映射模块根据派生字节选取候选字符或单词，策略模式先放入各类字符再执行既有洗牌。源码的 unbiasedIndex 名称不能代替严格均匀性证明：原实现有拒绝采样尝试与字节不足时的回退边界。本次完整保留这些细节，不宣称其输出具有未经审计证明的理想均匀分布。对已有协议，随手“修正”映射会破坏复现，因此没有这样修改。

执行引擎、自检与取消

引擎模块封装运行支持检查、Worker 路径、兼容执行、进度回调、取消及销毁。页面内嵌 hash-wasm 相关资源与纯 JavaScript 兼容计算资源。资源是否可以运行、是否能够分配内存，以及执行过程中是否出错，仍由原有逻辑判断；没有为了更快的界面反馈添加新的算法自动替代策略。

完整性检查会核对词表、内置 Pepper 及相关计算资源的 SHA-256 指纹。核心自检还使用既有测试向量比较结果，并检查真实进度事件数量和顺序。这些措施能够帮助发现资源损坏和某些实现不兼容，但不能证明任意被篡改的整个文件仍然可信：如果攻击者连程序和检查常量一起替换，文件内部的自检不是独立信任来源。

忙碌状态会锁定原有相关输入与操作，防止计算中混用参数。取消请求由原流程处理，清理和错误状态也沿用原行为。浏览器或操作系统强制结束进程则不属于应用能够保证优雅处理的情形。不要通过注释自检、跳过完整性失败或强行替换算法来“修复”无法生成；应找回可信完整文件，并在兼容环境使用原参数验证。

离线、剪贴板与设备

复制密码后可在“安全设置”中选择 0、30、60、120、180 或 300 秒自动清空剪贴板；默认 60 秒。重复复制会取消旧倒计时并重新开始。浏览器若拒绝后台剪贴板写入，页面会明确显示失败而不会假称已清空。

计算页面不加载外部字体、脚本或图片，也没有为这次改动增加网络请求或遥测。界面使用系统字体，帮助文档在本文件内。离线降低了通过页面网络发送数据的需要，但不代表设备本身安全。恶意扩展、键盘记录器、屏幕录制、系统级恶意程序，以及被替换的 HTML 文件，都不是一个页面的离线标签能够阻止的。

复制按钮将结果交给浏览器支持的剪贴板流程。系统剪贴板历史、跨设备同步、远程桌面或其他应用可能保留副本。不要把复制成功当作秘密已经安全保存，也不要把关闭页面当作自动清理剪贴板。本次没有新增剪贴板清除定时器；有此需求时，应使用设备自身的管理功能并理解其限制。

真实秘密应只在你信任的设备、浏览器和文件副本上输入。准备长期使用时，可以从可信渠道保留一份原始程序，并在独立可靠的位置记录其文件校验值，用于发现之后的意外变化。校验值需要来自可信来源；从同一份可疑文件重新计算出来的数字，不能证明这份文件最初就是安全的。

配置字段速查

format 用于区分单配置与历史合集；version 表示文件格式版本；protocol 记录派生协议和常规预设标识。configuration.mode 的值为 regular 或 pro，configuration.gen 的值为 char 或 word。这些是机器读取的固定枚举，不会随语言翻译。常规参数来自协议预设，专业参数来自对应配置字段。

passwordLength、useNumbers、useUpper、useLower、useSymbols、customSymbols、removeAmbiguous、enforceClasses 描述字符方案；wordCount、wordSeparator、wordCapitalize 描述单词方案。两套选项可以同时出现在配置里，但以当前选中输出模式为准。memKb、iterations、parallelism 描述专业 Argon2 参数，pepperLength 是下次随机生成的长度，featureCode 是特征码原文。

数值输入通常以字符串形式保存在配置中，再由计算时的整数规则验证；复选框使用 true 或 false。不要把字符串“false”当成布尔值 false，也不要把专业内存误填成 MiB 数字。文件的中文行尾解释只供人阅读，不参与计算。历史序号与下载文件名不是秘密派生输入；恢复旧密码应依靠文件内的配置字段和独立保存的原秘密。

常见问题与排查顺序

结果与以前不一样时，先核对是否用了同一协议版本，再核对主密码、特征码、实际 Pepper、模式、m、t、p，最后检查输出类型、长度或数量、类别选择、符号原文、易混淆开关、强制类别开关、分隔符及大小写。不要先怀疑显示语言或生成日期：它们不参与派生。若曾经手工编辑生成结果，也必须找回那份额外编辑记录。

生成失败时，阅读页面保留的具体错误。整数不合法就按原配置更正；内存分配失败就释放资源或换兼容设备；词表或核心完整性失败则重新取得可信文件。若正在恢复账号密码，不要尝试不断降低参数直到成功，因为那可能只是成功算出了另一个密码。若页面显示终止，重新开始需要一次新的完整计算。

历史消失时，检查是否换了浏览器、文件位置、浏览器用户目录或隐私模式，并查看是否清理过数据。配置导入失败时检查文件是否完整、是否为本程序支持的格式、是否被其他编辑器改变类型。遇到“结果尚未重新计算校验”，应补齐秘密后重新生成。任何排查示例都应避免把真实主密码或 Pepper 发到公开论坛或聊天中。

长期维护与改密

维护一份自己能够读懂的账号与配置对应关系，记录特征码规则和有效版本，备份非秘密配置与必要秘密，并进行周期性的恢复演练。演练不必每次都改网站密码；它主要验证自己仍然找得到完整输入、能够在预期设备完成计算，并且知道什么文件真正包含秘密。不要为了整理文件夹就删除唯一可用的旧配置。

怀疑秘密泄露、设备失陷或账号异常时，应在可信设备处理相关账号，按服务提供的流程改密、检查会话和恢复设置。更改本地主密码、Pepper 或特征码本身不会撤销网站正在接受的旧密码。只要网站端没更新，旧密码仍可能有效。多个账号共用同一主秘密时，应评估其影响范围，避免只改变一个界面输入就以为所有账号已经完成迁移。

本说明基于此文件实际代码组织撰写，界面升级不构成独立安全审计，也没有改变既有协议的优点或限制。一般安全阅读可参考下方 NIST 和 OWASP 官方资料；其服务器密码存储建议应结合场景理解，不能直接等同于本工具全部客户端派生参数。对于既有结果，复现优先要求始终是保存并使用原协议、原参数和原秘密。

Start here

PepperMint is a deterministic password derivation tool delivered as one HTML file. It runs the existing Argon2id pipeline locally, then maps the derived bytes to a character password or an English passphrase. Identical effective inputs, parameters and protocol produce the same result. Interface language and timing information are not derivation inputs.

The app does not create accounts, change website passwords or recover forgotten secrets. You must set the generated password at the correct service and verify that it works. There is no cloud recovery for a lost master password or Pepper.

Before using real accounts, practice generation, export, import and regeneration with fictional inputs. Learn the distinction between local history and secret-free exports. Examples in this guide explain structure; do not use them as real secrets. This guide is embedded and works offline. External references are opened only when you choose to follow a link.

Generate and reproduce

Open a trusted copy and choose 中文 or English. The Chinese title is 椒图密码生成器; the English title is PepperMint Password Generator. Language affects labels only. English passphrases always use the same embedded English wordlist.

Start in Standard mode. Enter a strong master password and a stable feature code identifying the service and account. Choose the output type and the exact options accepted by the destination website. Click Generate and wait for successful completion before copying the result.

Export the configuration and separately safeguard the original master password. Advanced mode also requires the original custom Pepper. In a separate test page, import the file, restore those secrets and generate again. Compare the results exactly before using the password on a real account. When reproducing an existing password, restore the original settings instead of choosing a similar-looking preset.

Master password & security

Use a long, unpredictable master password dedicated to this purpose. Avoid personal details, famous quotations, keyboard patterns and small variations of previously exposed passwords. Length helps only when the underlying choice is hard to predict.

Consider unrelated words chosen through a trustworthy random process, or a long random secret stored in a trusted password manager. For compatibility, this app still accepts a feature code without a master password. A public domain name alone is not a suitable secret source. Complex-looking output cannot repair easily guessed inputs.

Arrange reliable backups appropriate to your needs. NIST's public guidance emphasizes length, distinct passwords and password managers; this does not certify this app. Enable the destination account's additional authentication protections, such as MFA or passkeys, where available.

Feature codes

A feature code distinguishes services, accounts and password versions. It need not be secret, but it must be recoverable exactly. For new accounts, you might consistently use a structure such as example.com|personal|v1. Decide how to represent subdomains, account names and versions. The app does not parse URLs or remove spaces for you.

The existing protocol concatenates the normalized master password and feature code directly, without a new length prefix between them. Thus ab plus c and a plus bc have the same combined text. This behavior is preserved. Keep field boundaries and naming conventions stable; do not assume all distinct field pairs have distinct combined inputs.

For a new password version, record a new feature code and actually update the password at the website. Use the old version to reproduce the old password. Filename sanitization affects only the downloaded name, never the feature code inside the configuration.

Standard & Advanced

Standard uses the preserved preset: 328506 KiB of memory, 7 iterations, parallelism 1 and a fixed built-in Pepper. These values are supplied automatically. Performance still depends on the device and browser. Do not switch modes or alter effective parameters merely to recover an existing password faster.

Advanced exposes Pepper, memory, iterations and parallelism. Its original initial values of 65536 KiB, 3 and 1 remain unchanged. They are not a performance guarantee for every device. Integer validation and implementation limits also remain unchanged.

The built-in Standard Pepper is visible in the source file and is a public compatibility constant, not a private second key. A custom Advanced Pepper can serve as an additional secret only when it is unpredictable, private and reliably stored. The effective inputs and parameters determine the result; the mode label is not a secret.

Generate & preserve Pepper

A blank Advanced Pepper stays blank. A new random value is created only when you press Generate random. The length field is the number of characters to generate next; it is not a seed or a recoverable representation of the secret. Generating another Pepper changes this input and normally changes the resulting password.

Store the complete text accurately. Labels such as “64”, “512-bit” or an old date label cannot reconstruct it. Character count, bit count and actual secret content are different concepts. The original recovery-copy format is retained, including its legacy Pepper label; that label is not a backup of the secret.

Clear only empties the current Pepper field. It does not change a website password or remove other copies. A new random Pepper cannot replace a lost original when reproducing an old password. Treat Pepper changes as a documented password migration while you still have account access.

Memory parameter m

Memory is entered in KiB: 1024 KiB equals 1 MiB, and 65536 KiB equals 64 MiB. The human-readable capacity is a display aid; the original integer is the algorithm parameter. Higher memory can increase resource costs and may fail on constrained devices.

Memory is validated against the Argon2 specification: integer m in KiB must satisfy 8×p≤m≤4294967295; t is 1–4294967295 and p is 1–16777215. The extra approximately 4 GiB application cap has been removed, and the compatibility path uses a default memory budget derived from the same specification range. Valid parameters do not guarantee that this device or computation implementation can allocate the memory. Allocation failure is reported without reducing parameters. Runtime and buffer overhead require additional memory.

For a new configuration, test an acceptable cost on the weakest device you expect to use for recovery, then preserve the exact value. To reproduce an existing password, free resources or use a capable trusted device. Lowering m produces a different derivation; it is not a recovery workaround.

Iterations t & parallelism p

Iterations t control Argon2 passes. Increasing t generally increases work, but speed depends on hardware, memory and runtime load. The app accepts positive integers within Argon2id's 32-bit parameter range. Very large accepted numbers are protocol limits, not everyday recommendations.

Parallelism p is the Argon2 lane count, not a promise to launch that many browser CPU threads. Changing p changes the derivation layout and result even when measured performance looks similar. The existing maximum is 16777215, subject to memory and other checks.

For new configurations, balance recovery-device compatibility and tolerable waiting time with secret quality. For existing passwords, preserve m, t and p exactly. Increasing a parameter is a password migration: generate a new version, change the website password, verify login and then update recovery records.

Character password options

Character output maps derived bytes into the enabled number, uppercase, lowercase and custom-symbol pools. The original default length remains 16. For a new password, a longer length such as 20 or more can be useful if the destination accepts it in full. Longer output does not create entropy missing from a weak master secret.

Custom symbols use the original printable-ASCII filter and deduplication, covering code points 32–126. Order matters. Full-width symbols and emoji are not added to this pool. ASCII space is in range and can be included. Do not reorder an old symbol string and expect an unchanged result.

Exclude ambiguous characters removes O, 0, I, l, 1 and |. Include every selected character type enables the existing policy mapping and domain tag. Length must fit at least one character from each effective type. Preserve all of these options when recovering a password.

English passphrases

Passphrase mode uses the embedded EFF list and verifies its content and order. The original default is 6 words. The list is neither translated with the interface nor fetched online. Identical inputs produce the same English words in either language.

The separator is inserted between words; the default is an ordinary hyphen. Empty text means no separator. Spaces, hyphens and visually similar punctuation are distinct. Capitalize each word applies only the original capitalization rule. Preserve count, separator and capitalization exactly.

Confirm that the destination accepts the complete passphrase. Manual truncation, word removal or character edits are not recorded by the generator. Character-mode category switches do not impose number or symbol requirements on word mode.

Progress & completion time

Progress comes from completed internal Argon2id slices. Animation stays between confirmed progress values. Observing progress does not add data to the derivation. Remaining time uses the original overall and recent-rate estimate; waiting for enough samples is normal.

When elapsed plus estimated remaining time is greater than 3600000 milliseconds, the app also displays an estimated completion date and time. At or below one hour it does not. The timestamp is the current device time plus the estimate, in the device's local time zone, including the date across midnight. It updates with existing progress events and is not a guarantee. Sleep, throttling, load and clock changes can affect it.

Mapping, verification and cleanup may continue after the core finishes. Wait for the completion state and result. Cancellation and error handling remain unchanged. Opening this same-page guide does not actively cancel the calculation.

What local history contains

Save to history stores the complete configuration and a matching generated result when available. Each save creates a new numbered entry even for the same feature code. Pages contain 20 entries. Browser capacity is finite, and entries marked This page only are not persistent backups.

Existing local history contains plaintext master passwords, Peppers and results. This visual update does not turn it into an encrypted vault. Anyone or anything able to read that browser storage may access those secrets. Hiding a field or result protects only its visual display. Avoid saving real secrets on shared or public devices.

History belongs to the browser storage environment, not to the HTML file. Copying the file, changing browsers, clearing data or private browsing can affect access. Delete all history preserves the current form and result and does not erase downloads, backups or clipboard copies. The history implementation is unchanged.

Export, import & recovery

Configuration and history exports exclude master passwords, Pepper text and generated results. They preserve nonsecret recovery settings. Standard restores its built-in preset; Advanced requires re-entering any original private Pepper. Excluded secrets are absent, not hidden in encrypted form.

The existing export format uses Chinese JSONC line comments and supports legacy JSON. To preserve serialization and compatibility, interface language does not translate stored field names, comments, filenames or copied recovery text. The English guide explains these fields. Do not casually edit protocol identifiers, mode values or data types.

A single configuration restores the form; a bundle appends history entries. Illegal filename characters are sanitized in the name only. A saved result imported from an older file is not a freshly verified calculation. Restore the secrets and regenerate to confirm recovery. Copied parameters do not replace a complete secret backup.

Architecture & data flow

Two presentation fixes identify stale or unverified results and reset progress after configuration restoration. This parameter-range update removes extra m/t/p range restrictions and aligns the compatibility core memory budget with the specification. Hashing, memory-block computation, input encoding, wordlist, output mapping and configuration protocols are unchanged. The original single-file structure remains: markup supplies controls, styles define layout, embedded compatibility and Unicode resources stabilize behavior, cryptographic resources implement hashes and Argon2id, and the application coordinates generation, mapping, progress, clipboard and configuration history.

Generation clears the previous result, enters busy state, verifies resources, normalizes inputs, validates settings, captures the output specification, runs self-tests, constructs domain-separated input and salt text, invokes the engine, maps output, stores the current result and recovery description, and releases resources. Existing cancellation and exception paths still own this flow.

The appended presentation layer does not write input values, checkbox states, mode attributes or configuration protocol fields. It translates controlled UI text and accessibility attributes while excluding password results, history titles, configuration text and script data. The guide is static and never enters the derivation pipeline.

Unicode & exact inputs

Master password, feature code, Pepper and word separator use the fixed Unicode 15.0.0 NFC table. This avoids dependence on a browser's Unicode version. UTF-8 replacement behavior for isolated surrogates is also part of the preserved contract.

NFC is not autocorrection. Lookalike letters, full-width punctuation and spaces are not all interchangeable. To reduce reproducibility failures caused by accidental input, this version applies one additional fixed rule to the master password, feature code and manually entered Pepper in Advanced mode: leading and trailing ordinary ASCII spaces (U+0020) are ignored before derivation, while ordinary spaces inside the value are preserved. This rule applies only to U+0020 spaces. Leading or trailing carriage returns, line feeds, tabs, full-width spaces and other Unicode whitespace are not ignored and can still change the effective input and the derived result. Check pasted secrets for line breaks or other invisible characters, and keep a reliable exact copy of recovery data.

Generation may update fields to their normalized values under the existing rules; language switching does not. Custom symbols instead follow their original printable-ASCII filtering and deduplication, which is separate from Unicode support in master secrets.

Domains, salt & mapping

The ordinary character branch uses v1 and PwdGen-Salt-v1; policy output uses v2-policy and PwdGen-Salt-v2-policy; words use v1-words and PwdGen-Salt-v1-words. Text follows the existing vertical-bar concatenation format. Salt text is deterministic here, not a newly randomized server-storage salt on every click.

Internal hash length depends on output settings: max(length × 3, 64) for ordinary characters, max(length × 6 + 96, 96) for policy output, and max(count × 6, 64) for words, subject to validation. A longer password is not simply an extension of a fixed shorter result.

Mapping selects characters or words from derived bytes. Policy output includes each type before the existing shuffle. The function name unbiasedIndex is not proof of ideal uniformity: the preserved implementation has bounded rejection and fallback behavior. No unverified statistical guarantee is claimed, and those details have not been changed.

Engine, self-tests & cancellation

The engine owns support checks, Worker execution, compatibility execution, progress callbacks, cancellation and destruction. Embedded hash-wasm is unchanged. Only the JavaScript compatibility resource's memory-budget validation has been aligned with the specification; its computation is unchanged. No new algorithm substitution or scheduling policy has been introduced.

Integrity checks compare SHA-256 fingerprints for the wordlist, built-in Pepper and computation resources. Existing self-tests compare vectors and progress-event counts and order. These checks detect some damage and incompatibility; they are not an independent authenticity guarantee if an attacker replaces the whole file and its check constants.

Busy state locks the original controls to prevent mixed settings. Cancellation, cleanup and errors retain their existing behavior. Forced browser termination is outside graceful application control. Do not disable checks or substitute an algorithm to bypass a failure. Recover a trusted complete file and verify the original settings in a compatible environment.

Offline use, clipboard & devices

After copying a password, Security settings can auto-clear the clipboard after 0, 30, 60, 120, 180 or 300 seconds; the default is 60 seconds. Copying again cancels the old countdown and restarts it. If the browser denies a delayed clipboard write, the page reports the failure instead of claiming the clipboard was cleared.

This update adds no external fonts, scripts, images, automatic requests or telemetry. Fonts are local and the guide is embedded. Offline operation does not secure a compromised device, malicious extensions, keyloggers, screen recording or a replaced HTML file.

Copy actions use the existing browser clipboard path. Clipboard history, synchronization and other software may retain copies. Closing the page does not automatically clear them. This update adds no clipboard-erasure timer.

Enter real secrets only on trusted devices and in trusted file copies. Preserve a trusted original and, where useful, a checksum obtained through a reliable independent channel. A checksum computed from a suspicious file cannot by itself establish that file's authenticity.

Configuration field reference

format distinguishes a configuration from a history bundle. version is the file format version; protocol identifies derivation and Standard presets. configuration.mode is regular or pro; configuration.gen is char or word. These machine-readable values do not change with language.

passwordLength, useNumbers, useUpper, useLower, useSymbols, customSymbols, removeAmbiguous and enforceClasses describe character output. wordCount, wordSeparator and wordCapitalize describe words. Both groups can be stored, but only the active output mode applies. memKb, iterations and parallelism are Advanced parameters; pepperLength is the next random-generation length; featureCode is the original identifier.

Numeric inputs are generally stored as strings and validated as integers at calculation time. Checkboxes use booleans. Do not confuse the string “false” with false, or enter a MiB number in a KiB field. Comments, history numbers and filenames are not secret derivation inputs.

Troubleshooting

If a result differs, check protocol version, master password, feature code, effective Pepper, mode, m, t and p, then output type, length or count, categories, exact symbols, ambiguity and policy switches, separator and capitalization. Language and date are not inputs. Any manual edits made after generation require their own record.

For failures, read the actual error. Restore valid original integers, free memory or use a compatible device, and replace damaged resources with a trusted file. Do not lower parameters until something runs when recovering an old password; that can successfully compute the wrong password. A cancelled task must be started again.

Missing history can result from browser, file location, profile or privacy-mode changes, or cleared data. Check import completeness and data types. An imported unverified result should be regenerated with the original secrets. Never post real master passwords or Peppers while asking for help.

Long-term maintenance

Keep a clear account-to-configuration record, feature-code convention and version history. Back up nonsecret settings and required secrets, and occasionally rehearse recovery on expected devices. A rehearsal need not change the website password; it checks that the complete inputs and a working environment remain available.

If compromise is suspected, handle affected accounts from a trusted device and follow each service's password, session and recovery procedures. Changing a local master password, Pepper or feature code does not revoke a website's old password. The website must actually be updated. Consider the scope of a shared master secret across accounts.
